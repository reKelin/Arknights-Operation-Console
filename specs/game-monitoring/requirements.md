# 游戏监控与同步需求

- REQ-MONITOR-001：默认轴必须为空，并提供安全的清空入口。
  - AC-MONITOR-001：新进程启动时没有预置操作点；按钮或全局 F4 第一次请求后进入 3 秒确认期，第二次请求才清空事件，轴标题和 `stageId` 保留。
- REQ-MONITOR-002：窗口必须支持自由调整尺寸并提高整体可读性。
  - AC-MONITOR-002：默认约 960×300、最小约 760×260、宽高均可调整；现有正文和控制字体整体增加约 2–3 px，时间轴使用新增高度。
- REQ-MONITOR-003：界面必须支持深色与浅色主题。
  - AC-MONITOR-003：视图菜单可以即时切换主题；重启后恢复上次主题，轴内容不因此持久化。
- REQ-MONITOR-004：用户必须能选择官方 PC 客户端窗口作为实时观测源。
  - AC-MONITOR-004：候选列表只包含由 `Arknights.exe` 持有、可见且可捕获的顶层窗口；选择后显示窗口标题、分辨率和连接状态。
- REQ-MONITOR-005：实时观测必须识别关卡边界与游戏速度状态。
  - AC-MONITOR-005：至少区分非战斗、关卡开始、1×运行、2×运行、0.2×运行、暂停、部署减速、方向调整和未知状态，并为每次观测提供可信度。
- REQ-MONITOR-006：费用条必须为权威时钟提供可校正的视觉锚点。
  - AC-MONITOR-006：根据设置的费用周期分母识别当前费用相位和循环回绕；费用条满或暂时不可读时不产生虚假回绕。
- REQ-MONITOR-007：计时必须只在关卡实际运行后开始并跟随游戏状态。
  - AC-MONITOR-007：首次可信运行观测建立 F0；1×、2×、0.2×按对应倍率累计，暂停冻结，费用观测可校正累计帧；未知、过期或失联观测冻结并显示不可信。
- REQ-MONITOR-008：退出关卡必须重置计时但保留当前轴。
  - AC-MONITOR-008：连续多帧确认非战斗后状态回到等待且帧归零；轴标题、`stageId`、操作点及其顺序均不改变。
- REQ-MONITOR-009：用户必须能设置费用逻辑秒分母。
  - AC-MONITOR-009：支持 30、45、60、90 和 15–150 的自定义整数；计时显示 `MM:SS:FF/N`，绝对游戏帧继续显示为 F 值，AxisLink `timebase.fps` 固定为 30。
- REQ-MONITOR-010：用户必须能选择录屏并复用实时监控链离线分析。
  - AC-MONITOR-010：接受 MKV/MP4，后台输出分析进度和内存中的关卡区段、状态、费用相位、30 Hz 游戏帧轨迹；可以在时间轴上定位轨迹帧。
- REQ-MONITOR-011：录屏分析不得自动生成或覆盖轴事件。
  - AC-MONITOR-011：开始、完成、取消或失败录屏分析后，当前轴内容保持不变。
- REQ-MONITOR-012：监控必须遵守失效安全边界。
  - AC-MONITOR-012：窗口关闭、捕获失败、尺寸变化、FFmpeg 缺失、格式不支持或观测超时均返回中文结构化错误；不得继续盲目推进计时。
- REQ-MONITOR-013：自动验证必须覆盖不依赖真实窗口的核心状态转换。
  - AC-MONITOR-013：Windows CI 使用合成像素和从 `V:\OBS` 派生的小型 ROI 夹具验证状态分类、费用回绕、时钟倍率、离关归零、分母显示与录屏元数据处理；真实窗口选择与 WGC 生命周期保留人工验收。
