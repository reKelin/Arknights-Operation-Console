# 暂停执行需求

- REQ-PEX-001：真实输入必须默认关闭，并且只在用户明确启用代理、确认首次键位和目标游戏窗口位于前台后发送。
  - AC-PEX-001：应用重启、离关、失焦、换源、错关、时钟不可信或 K 接管均会停止后续输入；未确认技能／撤退键位时对应事务在首个输入前失败。
- REQ-PEX-002：执行器必须只使用 Windows 用户输入 API，不访问游戏内存或注入游戏进程。
  - AC-PEX-002：部署只使用 `InjectTouchInput`；技能和撤退在触摸选中后只使用经确认的标准 Windows 键盘模拟。
- REQ-PEX-003：三个操作都必须在可信暂停边界内执行。
  - AC-PEX-003：部署在持续暂停中完成卡位拖拽、落点和朝向；技能／撤退使用“暂停、选中、确认仍在事务允许的短暂选中过渡、发送绑定键、恢复暂停”的事务。
- REQ-PEX-004：每个可能改变游戏状态的步骤前后必须取得新鲜画面并重新检查安全门。
  - AC-PEX-004：窗口前台、客户区尺寸、关卡、监控会话、画面时效和可信时钟任一不满足即取消活动触点和按键，停止当前批次且不补发。
- REQ-PEX-005：事务内预期视觉状态必须与事务外的异常状态分开处理。
  - AC-PEX-005：部署／选中产生的 `DeployingOperator`、`AdjustingOperatorFacing` 或短暂 `PointTwoXRunning` 先进入事务内隔离区；只有事务前后都取得可信暂停、非满费费用锚点证明逻辑帧未推进且窗口与捕获连续时才能提交事务。中间样本不得推进 ProxyClock，也不得恢复被丢帧或过期打断的信任；缺少不推进证据时结果必须为 `uncertain` 并停止。
- REQ-PEX-006：调度必须在目标帧前准备暂停，并在可信目标帧按稳定顺序逐项执行。
  - AC-PEX-006：同帧按轴顺序与稳定 ID 串行；每项重新取图；当前帧超过目标帧时生成明确失败回执并停止，不能静默消费或补发。
- REQ-PEX-007：输入 API 返回成功不得等同于游戏操作成功。
  - AC-PEX-007：只有新鲜后置画面满足该动作的视觉结果条件时生成 `confirmed`；输入已发但证据不足时生成 `uncertain` 并保持暂停，等待用户确认或接管；输入未发或明确失败分别生成 `failed` 或 `cancelled`。
- REQ-PEX-008：执行回执必须足以支持 K 接管后的前缀保留。
  - AC-PEX-008：每条回执包含稳定 `eventId`、严格递增 `receiptSequence`、`plannedFrame`、可空 `observedFrame`、可空源时间戳、状态和原因；同帧完成顺序只能按回执序号判断。
- REQ-PEX-009：K 接管必须能中断任意执行阶段并完成输入收尾。
  - AC-PEX-009：中断立即阻止后续步骤，释放活动键和触点；已经发送但未取得结果证据的动作记为 `uncertain`，尚未发送的动作记为 `cancelled`，并与停止原因分别保留。
- REQ-PEX-010：代理必须从下一局 F0 武装，最后一项结束后保持暂停。
  - AC-PEX-010：武装不消费当前局事件；收到可信 F0 后开始调度；最后一项无论已确认或等待人工确认都不自动恢复运行，普通停止不创建轴版本。
