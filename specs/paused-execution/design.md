# 暂停执行设计

## 模块边界

`executor.rs` 持有异步事务、取消代次、回执序号和待人工确认项；`executor/touch.rs` 与 `executor/keyboard.rs` 只封装 Windows 输入；`executor/vision.rs` 发布带序号和源时间戳的最新执行画面并提供结果比较。捕获回调只复制并发布画面，不等待事务。Runner 在后续集成中持有调度游标、ProxyClock 和 UI 快照，不把时钟判断移入 React。

执行线程逐项运行，同一时刻只有一个事务。取消代次在 K 接管、失焦或安全门失败时递增。触摸与键盘封装都在错误、取消和析构路径释放活动输入。

## 调度与暂停证明

Runner 只在 `ClockQuality::Trusted`、同一关卡和新鲜窗口源上调度。下一操作进入提前量后先请求暂停；新画面证明 `Paused` 且仍为计划帧时，执行器建立 `PauseProof`，其中包含窗口、客户区、监控事件序号、源时间戳和计划帧。超过计划帧属于 `missedTarget`，不进入动作事务。

事务允许的交互状态有严格范围：部署可以出现 `DeployingOperator` 和 `AdjustingOperatorFacing`；技能／撤退选中可以短暂出现 `PointTwoXRunning`。当前视觉分类在选中界面隐藏暂停控件后不能独立判断引擎是否暂停，因此进入隔离区后时钟质量立即显示为暂未确认并冻结，不能继续显示 `Trusted`，也不能仅凭旧的 `PauseProof` 宣告安全。事务结束时必须重新观察可信 `Paused`，并用事务前后的非满费费用相位在视觉分辨率和既有误差范围内证明逻辑帧未推进；满费、费用不可见或锚点变化均缺少不推进证据，结果进入 `uncertain` 并停止。费用相位只证明时间边界，不证明技能、撤退或部署成功；动作仍需下节所述的独立结果证据。暂存样本不送入 ProxyClock、不作为新的可信锚点。捕获不连续、画面过期、窗口或尺寸变化、出现 1×/2×推进时立即撤销暂停证明并停止。

## 输入事务

- 部署：从新鲜暂停画面唯一定位干员卡，拖到侧视格子投影，再拖动朝向。每次拖拽之间重新取得画面并检查事务安全门。
- 技能／撤退：从暂停画面按正视投影选择目标，在允许的短暂选中过渡内发送用户已确认的绑定键，随后等待新鲜暂停画面。执行器不猜测或读取游戏注册表键位。
- 键盘配置使用受限虚拟键值；首次使用前必须由用户确认当前配置。按键序列固定为 key-down/key-up，取消路径对所有活动键补发 key-up。

## 结果证据与人工确认

部署的自动确认同时要求：目标干员在部署栏的唯一匹配消失、目标格子区域发生足够变化，并且连续新鲜画面回到暂停。撤退的自动确认要求目标格子区域稳定变化且部署栏出现新的有效卡位；技能只有在可配置键发送后观察到目标区域变化并回到暂停时才确认。画面效果、遮挡或特殊干员使这些条件不充分时，回执进入 `uncertain`，执行器保持暂停并停止队列。

`resolve_uncertain` 是可执行的人工确认入口：用户可以把待确认回执改为 `confirmed` 后继续，或改为 `failed` 并停止。人工确认改变回执状态但不伪造视觉时间戳；K 接管则保留 `uncertain` 和原因。

UI 必须在事务开始前说明能力边界：满费或选中界面遮挡费用条时无法自动证明零帧，技能特效或目标遮挡时也可能缺少动作证据；这些情况会保持暂停并要求人工确认，不显示自动成功。

## 回执

每次下一局可信 F0 接管时分配 session 内单调的 `run_id`。`ExecutionReceipt` 包含 `run_id`、`event_id`、`receipt_sequence`、`planned_frame`、`observed_frame`、`source_timestamp_ns`、`status` 和 `reason`。序号由执行器单调分配；接管续录只允许消费与当前 `ProxySnapshot.run_id` 相同的回执。状态含义如下：

- `confirmed`：游戏结果已有视觉证据或用户明确确认；
- `uncertain`：输入已经可能生效，但证据不足；
- `failed`：输入未完成或观察到明确错误；
- `cancelled`：在该动作首个可能生效的输入之前中断。

发送输入与确认结果是两个阶段，因此取消时可以正确区分未开始、已发送待确认和最后一项已完成。
