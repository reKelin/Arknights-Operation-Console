# 架构约束

本文记录开发必须保持的语义。实现与本文不一致时先确认差异，涉及这些边界的变更应作为明确设计变更处理，不能通过局部重构隐式改变。

## 产品与术语

Console 面向 Windows 10/11 和明日方舟官方 PC 客户端，提供计时、录轴、作战轴编辑与执行。游戏集成使用窗口捕获、视觉识别和系统输入 API；不读取游戏内存、注入代码或解析游戏网络协议。UI 不展示游戏画面、关卡地图或战斗模拟。

| 术语 | 含义与边界 |
|---|---|
| 游戏帧 / F0 | 固定 30 Hz 的逻辑帧；F0 是可信进关运行起点，不是视频第一帧 |
| 来源时间 | WGC 会话内单调时间或录屏原始 PTS/time base，不是主机收到回调的时间 |
| HumanClock / ProxyClock | 人工操作与代理执行各自独立的权威时钟状态 |
| DraftAxis / DraftEvent | 会话内可不完整的轴与操作草稿 |
| AxisLink v2 | 可交换的已确认玩家操作协议，不包含运行策略、候选或会话版本 |
| RecordingAttempt | 真实进关至离关的录制场次，录屏区段不冒充实机场次 |
| AxisRevision | 带父链的轴版本；接管与录屏合并创建子版本，父版本保留 |
| runId / ExecutionReceipt | 一次代理运行及其有序结果证据，不能跨运行复用 |
| 录屏候选 | 带来源和时间范围的待校对操作，可信度不等于参数完整性 |

## 职责与架构理由

Rust 持有时钟、关卡、轴、会话版本、调度和输入副作用，React 通过生成命令提交意图并显示快照，只维护展示与未提交表单状态。这样执行门禁和状态转换只有一处权威实现，详见 [ADR 0001](adr/0001-state-and-protocol.md)。

窗口与录屏共享视觉识别基础能力，但保留各自来源时间和完整性证据。HumanClock 与 ProxyClock 独立持有可变状态，仅共享无状态换算函数，详见 [ADR 0002](adr/0002-time-and-execution-evidence.md)。

捕获回调非阻塞发布观测与执行画面；队列有界、序号与丢失计数可追踪。窗口会话切换后，时间戳和旧证据不可跨会话使用。

## 协议、关卡与持久化

- [AxisLink Schema](../protocol/axislink.schema.json) 是协议唯一规范源。部署包含干员、格子和朝向；技能与撤退仅含格子。提醒、暂停和代理策略留在运行时。
- 部署单位在人机界面使用中文名称，Rust 按固定版本单位目录解析为唯一内部键；未匹配或重名保持待校对，不猜测。草稿与 AxisLink 保存内部键，部署单位同时接受干员 `char_` 和召唤物 `token_`；显示名称不能代替协议键。
- 朝向 `none` 表示确认不需要选择朝向，空值仍表示待识别；执行 `none` 时只拖放，不发送第二次朝向手势。已知无朝向的棋子自动填写 `none`。
- 格子使用 A1–I36，字母从下向上、数字从左向右；地图 JSON 的行序需反转，地图可用时按实际宽高校验。部署与选中分别使用对应的侧视/正视投影。
- 期望关卡与 OCR/手动确认的观测关卡独立持有。错关不停止计时，但阻止实时录轴与调度；期间错过的操作不得补发。
- 关卡目录固定来源版本，地图与头像按需缓存；OCR 歧义保留待确认状态，不能猜测唯一匹配。
- 主题和监控设置可持久化；轴草稿、录屏分析和会话版本只保存在内存与显式导出的文件中。
- 应用标识为 `io.github.kelin.arknights-operation-console`；包名和二进制名为 `arknights-operation-console`。标识变化会改变配置路径。

## 时钟与录轴

- 首次可信运行观测建立 F0；费用锚点约束时间，满费时按可信速度外推，暂停冻结，未知/过期观测不推进。离关归零，保留当前轴。
- 费用逻辑秒分母只影响周期分析和显示，不改变 30 Hz 事件帧。
- 丢帧后普通高置信观测不能直接恢复 trusted；需要有效费用锚点。双时钟交接仅传递帧、余数、来源时间和锚点，不传递调度历史。
- 游戏前台 P 记录带来源、帧范围和质量的操作；参数确认与时间确认独立。范围外改帧必须显式确认人工校正。
- 编辑器批量确认时间按每个勾选操作自身的帧数提交，先校验全部目标再统一更新；任一目标失败不得部分确认。多选中存在范围外时间时，人工校正确认覆盖明确显示的本批目标。
- 录屏探测、解码和识别在后台执行，不在窗口命令中扫描文件；取消或更换来源后旧任务不能向新会话发布结果。
- INFO/ERROR 日志默认记录并有界持久化；调试开关仅控制 DEBUG。设置支持历史、错误查看和 ZIP 导出；不记录视频路径、图像或凭据。
- 录屏主扫描只解码一次，按来源帧序号抽样并保留所选帧的原始 PTS，不以平均帧率补造时间；断点、倒退、缺片段或溢出使映射不可信。
- 录屏草稿以操作首次可见响应处的时钟估计值落点，暂停后恢复运行不能代替操作发生时刻。技能需后续技能条或效果证明，不能仅凭取消选中判定；效果出现时间也不能直接冒充输入时间。误差范围不能代替估计值，估计值不自动获得时间确认。
- 离线录屏通过按钮图形定位判断倍速与暂停，不以固定位置亮度代替图形；无法辨认的状态保留不确定性。游戏时间积分倍速与暂停，来源时间仍为视频 PTS，两者分别显示。
- 录屏交互窗口按面板出现/消失划分，暂停中的连续操作也须分别结算；操作候选状态与计时状态分离。READY 技能的费用消耗不能单独证明部署，技能后续证据按运行采样观察，暂停等待不消耗证据窗口。进关淡入未结束的暗色控件不能启动 F0。
- 离线费用条未校准时不作为时间锚点；暂停优先于部署/选中减速。录屏回归使用独立核验的书签与速度区间，逐项检查操作数量、种类及 30 Hz 游戏帧误差，不能以识别输出反向生成标准答案。
- 录屏默认打开已识别关卡的最长区段，避免把片头短暂误检当作完整作战；其他区段仍可手动选择。视觉操作候选与时间可信度独立，时间不可信的候选保留待校对，不自动获得执行或导出权限。
- 已知字段可以自动填入录屏草稿；未知种类、干员、格子、方向和时间保持待校对。参数或时间未确认时阻止导出与代理。
- 离线参数识别以编队页和独立助战位提供候选，进关后用完整头像库核对实际部署栏；编队名单不能排除助战或录像未展示的单位。候选包含关联召唤物，并与选中面板、部署栏变化交叉确认；地图投影只在关卡匹配后使用。操作窗口允许补读原始帧细化响应边界，时间区间须同时包含输入响应与时钟映射误差，不能仅因视频帧定位准确就宣称游戏帧唯一。
- 头像特征随程序内置，不在分析时逐个下载；维护时先用 `npm run stages:sync` 同步固定版本目录，再用 `npm run portraits:sync` 从目录指定的头像版本生成特征和索引。
- 同帧操作按轴顺序与稳定 ID 执行；编辑操作不触发追赶执行。

## 执行与接管

- 真实输入默认关闭，用户显式启用并确认首次键位后才可执行。代理只从下一局可信 F0 武装，不追赶当前局。
- 部署使用 InjectTouchInput；技能/撤退在选中后发送已确认的标准键盘绑定。每一步都检查前台窗口、尺寸、关卡、会话、画面时效和可信时钟。
- 暂停选中过渡中的视觉状态进入隔离区，不推进 ProxyClock，也不恢复可信度。事务前后需新鲜暂停画面和非满费费用锚点证明帧未推进；动作成功另需结果证据。
- 输入 API 返回成功不代表游戏操作完成。回执使用 confirmed、uncertain、failed、cancelled；证据不足保持 uncertain 并停止，人工确认不能伪造视觉时间戳。
- K 接管、界面停止、失焦、错关、尺寸变化或时钟不可信时停止队列并释放键与触点。最后一项结束后保持暂停，不自动继续游戏。
- K 先取消并等待最终回执，再按本次 runId 和 receiptSequence 构造子版本前缀；遇 uncertain 保留待确认并停止，遇 failed/cancelled 停止，未执行尾部留在父版本。普通停止不创建版本。
- 接管时间必须来自最终暂停证明和 ClockHandoff，不能读取 React 显示帧。时间不可信时保留证据，但禁止继续录制或武装。
- 一次录屏合并只处理一个区段，偏移由明确锚点确认；候选需严格晚于接管边界。以分析 ID、区段和候选 ID 去重，同帧同格同类但来源不同的冲突由用户选择，不能自动当成重复。
- 合并保留父版本与已执行前缀，负帧、溢出、倒置范围或混合区段返回错误。

## 刻意保留的界面行为

工作台默认约 1100×280、最小约 860×280，编辑与设置页可增高；默认置顶，最小化到任务栏，可从任务栏恢复窗口，关闭直接退出。使用三模式工作台和单轨时间轴，支持深浅主题、滚轮横移、Alt+滚轮缩放与同帧堆叠。

Console 前台 H 打开编辑页，Ctrl+S 导出；文本输入焦点下保留正常编辑语义。P/K 仅在对应模式和选定游戏窗口前台生效。切换展示模式不等于授权执行。

代理后端逻辑存在不代表产品入口已开放或实机验证完成。真实录屏识别、暂停事务、完整接管/接续循环和安装升级须提供实机证据后才能宣称可用。
